PURPOSE
Fix the recurring logout problem that happens after QA / Agent login.

ROOT CAUSE ALREADY IDENTIFIED
The current backend stores only one activeSessionHash.
Every successful Superadmin login overwrites that hash.
When the QA agent logs in, the owner's existing browser session becomes invalid.
On refresh, the owner is therefore sent back to the login screen.

V22.3 changes this to a bounded multi-session registry so the owner's browser and QA agent can stay authenticated at the same time.

SECURITY REQUIREMENTS
- Keep signed HttpOnly cookie authentication.
- Keep Secure cookie in production.
- Keep SameSite=Strict.
- Keep CSRF protection.
- Keep existing session TTL; DO NOT extend it in this phase.
- Never store passwords or auth tokens in browser localStorage/sessionStorage.
- Never expose the session token to frontend JavaScript.
- Maximum active Superadmin sessions: 12.
- Logging out must revoke ONLY the current session.
- Preserve backward compatibility with the legacy activeSessionHash so the owner's currently open session survives migration/restart when possible.

DO NOT CHANGE
- Hero
- Date Filter
- KPI V22.2 visuals
- System Health
- Command Center
- Transactions
- Sidebar
- GitHub Module behavior
- profile/encryption behavior
- any business data

PRODUCTION SERVICE RESTART — DISCOVER, DO NOT GUESS
==================================================

This is a backend change, so the live Node service must be restarted.

Do NOT guess a systemd or PM2 service name.
Discover the running production process non-destructively:

1. Inspect:
   ps -eo pid,ppid,cmd | grep -E '[n]ode .*server/index\.js'
2. Inspect the process cgroup for the live PID:
   cat /proc/<PID>/cgroup
3. Inspect systemd running services only if the cgroup indicates systemd ownership.
4. If an exact owning systemd unit is positively identified, restart ONLY that unit.
5. If the process is managed by another supervisor, identify it from the process tree/config before using that supervisor.
6. Do NOT kill the production process manually if ownership is unresolved.
7. After restart verify:
   - GET /api/health returns 200
   - /admin loads
   - production backend is running from /67

Return the exact restart method and service/process identity used.
