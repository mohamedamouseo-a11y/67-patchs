OBJECTIVE
Replace the over-compressed V32.2 operations geometry with a readable executive layout for:
1) العمليات المباشرة / Live Operations
2) العمليات الجارية / Current Operations

WHY V32.3
V32.2 still produced a diagnostic QA commit marked VISUAL_FAIL_PERSISTS. The V32.2 corrective layer forced micro typography (roughly 5–7px in several descendants) and a 258px hard card height. V32.3 intentionally stops compressing operational information and allows the second command row to grow naturally.

PATCH
Fetch and execute exactly:
https://raw.githubusercontent.com/mohamedamouseo-a11y/67-patchs/main/67-admin-v32.3-operations-readable-executive-layout-apply.sh

EXECUTION
1. cd /67
2. Download patch to /tmp/67-admin-v32.3-operations-readable-executive-layout-apply.sh
3. chmod +x it.
4. Execute it.
5. Require BUILD=PASS.
6. Activate live runtime using the same verified restart mechanism used for V32.2.
7. Confirm local dist, origin and public index hashes match.
8. Browser QA at 1920x1080.

STRICT SCOPE
Allowed:
- CSS geometry/typography/styling of .live-card and descendants
- CSS geometry/typography/styling of .ops-card and descendants
- natural row growth required to keep operational data readable

PROTECTED — MUST NOT CHANGE
- Hero
- Date Strip and date logic
- KPI
- System Health
- Revenue & Performance/chart/donut
- Sidebar
- Transactions/ledger
- liveNotifications data and logic
- operations counts/data
- backend/auth/API/routing/permissions

DO NOT
- rewrite JSX
- remove or hide real information
- alter counts or labels
- use font-size below 7px for ordinary descriptive/status text
- use font-size below 8px for primary row labels
- force the two operations cards back into a 258px/286px hard compression
- source-push /67 before ChatGPT visual approval

QA METHOD
Before measuring each card:
- scrollIntoView({block:'center', inline:'nearest'})
- wait for layout stability
- then measure real DOM geometry

VISIBLE definition:
- exists in DOM
- display != none
- visibility != hidden/collapse
- opacity > 0
- rect width/height > 0
Do not fail visibility merely because an element was below the initial viewport before scrollIntoView.
